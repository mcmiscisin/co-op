# Representative-Lesson Selection for Step 2

The next small group should be selected from actual supplied lesson material, not from guessed lesson numbers or titles.

Choose approximately 3–5 lessons whose source material collectively stresses different engine capabilities.

## Preferred coverage

At least one lesson should emphasize each of the following across the group:

1. **Mostly multiple-choice / algebraic manipulation**  
   Confirms ordinary scoring and expression rendering at scale.

2. **Fill-in numeric or multi-field responses**  
   Exercises the two-try credit policy and numeric parser.

3. **Graphs, diagrams, coordinate geometry, or visual interpretation**  
   Tests package-supplied verified visuals and responsive layout.

4. **Multi-step word problems or formula work**  
   Tests mixed response groups, variable definitions, rounding instructions, and worked solutions.

5. **A lesson structurally unlike Lesson 89, if available**  
   For example, a different number of instructional topics, only one exercise section, unusual notation, or a new answer format. This is important because the foundation should be generalized from evidence, not force every lesson into Lesson 89's exact shape.

## Selection rule

Do not select lessons merely because they are consecutive. Select them because they expose different content structures.

After these representative packages pass validation, revise the package schema only where the source material proves a real need. Then the remaining lessons can be added incrementally without repeatedly redesigning the engine.
